# 多手机自动排班与流程调度工具

这是一个基于 AutoJs6 / Hamibot 的 Android 多设备自动化预约排班工具。针对周期性定时放号、几秒内秒空的场景，通过多台手机协同运行、毫秒级定时对齐、排班规则自动分发与时段回退，解决人工盯秒操作繁琐和单机易卡死的问题。

---

## 一、为什么做这个工具？

很多政务或医疗便民业务（如专科门诊）实行每天清晨固定时间放号，号源极少，几十秒内就会被约满。

如果纯靠人工操作：
1. 每天清晨盯秒操作非常折磨人，手速和网络稍慢就抢不到；
2. 单台手机跑自动化也不稳，遇到偶发网络卡顿或系统弹窗，当天就彻底失败；
3. 出诊人员排班经常变动（比如周一上午出诊，下周又临时调休），如果把人员和时间写死在脚本里，每次变动都得重新改代码。

因此，这个工具的核心目的就是：**把多台手机组织起来协同操作，到点自动进页面、按规则选人占座，成功后响铃叫醒人来付款。**

## 二、从“多个独立脚本”到“统一调度框架”的演进

这个项目不是一开始就设计成框架的，而是经历了一个非常真实的工程演进过程：

```text
【第一阶段：单机硬编码脚本】
一台手机，一份脚本，所有点击坐标、等待时间和排班规则全写死在代码里。能跑，但极度脆弱。
       ↓
【第二阶段：多机复制带来的“维护地狱”】
为了提高命中率引入多台手机，不同手机屏幕分辨率和手势距离完全不同；加上人员频繁调休，
导致手里堆了多份类似脚本（如 Xiaomi_周12.js、vivo_周34.js），每次排班微调都要逐台改代码。
       ↓
【第三阶段：架构解耦与调度抽象】
发现流程主干完全相同，变动的只有“屏幕物理坐标”和“出诊排班表”。
于是彻底重构：将机型坐标抽离为设备配置（JSON），排班映射抽离为规则表，驱动统一的核心执行引擎。
```

## 四、系统架构与核心设计

```text
排班规则表 (Rules) → 调度引擎 (Engine) → 设备参数 (Adapter) → 终端执行 → 闹铃/震动人工交接
```

### 1. 屏幕坐标与代码彻底分开（设备适配层）
不同品牌和型号的手机屏幕大小完全不同。我们将每台手机的坐标、滑动距离全部提取成独立的 JSON 配置文件（存放在 `config/devices/` 下）。接入新手机只需要量一下新坐标填进配置，核心代码一行都不用改。

### 2. 排班规则单独配置（业务调度层）
谁星期几出诊、是上午还是下午、优先选哪个时段，全部写在 `config/rules/shift_schedule.json` 规则表里。脚本启动时根据当天星期自动调度，遇到人员调休改表即生效。

### 3. 毫秒级时间微调（执行层）
* **提前 30 秒预热**：放号前半分钟，手机自动打开 App 并停留在待选列表页，把冷启动耗时留在放号前完成；
* **提前 30 毫秒发包（05:59:59.970）**：提前几十毫秒发出点击事件，刚好用动作和系统渲染的耗时抵消掉网络延迟，卡准放号瞬间切入排班表；
* **时段快速回退**：首选时段如果显示没号，脚本在 100 毫秒内自动切换并尝试备选时段，不卡死在单个时段上。

### 4. 人机分工，守住安全底线（安全提醒层）
程序只负责速度敏感的“选人、选时段、占座”。一旦占座成功进入最终确认页，脚本立刻停止操作，并触发手机持续震动和系统闹铃，由人来做最终核对并完成指纹/人脸支付。

## 五、项目成果

* **架构成效**：将原本分散维护的多套单机脚本抽象为统一执行框架，使设备差异、坐标参数和排班策略彻底独立配置，后续规则变动零代码修改；
* **实战验证**：通过多终端并发协同对冲单机偶发卡死，显著降低了人工清晨盯秒的操作成本，已在多台真机上长期稳定运行。

## 八、使用说明

1. 手机安装 **AutoJs6** 或 **Hamibot**，开启“无障碍服务”并允许后台运行；
2. 如果使用已有支持的机型（如小米 13、vivo），直接导入对应的专机脚本或通用引擎；
3. 如果是新手机，打开开发者选项里的“指针位置”，量出对应位置的坐标，参考 `config/devices/template.json` 填好即可；
4. 每天放号前启动脚本，保持手机亮屏，到点自动执行，成功后会通过响铃和震动提醒付款。
